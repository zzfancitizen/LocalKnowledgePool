# 入门:管理用户授权

> [!abstract] 目标
> 用 [[授权模型 (Role-Binding-PathBinding)|Role 与 Binding]] 把用户/服务(technical client)分配到系统交付角色或自定义角色。工具:[[uctl 命令行工具|uctl]] 或 [[Workspace 与 CAD|Workspace]]。

> [!tip] 层级遍历
> 要让用户从根 org 遍历层级(用 Workspace 导航),须在 `Binding` 设 `pathAccess.enabled: true`(Derived Authorizations)。

## 常用命令

```bash
uctl edit binding accounts.admin -p /sample-org
uctl apply -f <path/to/yaml>
uctl show-tree folder <name> -p <path> --types binding
```

## 五个典型场景

### 1. 追加 Organization Admin
`uctl edit binding accounts.admin -p /sample-org`,在 `subjects` 加用户 email 或 technical client 全路径。

### 2. Folder Admin
新建引用 `accounts.admin` role 的 `Binding`(path 指向目标 folder)。

### 3. Authorization Admin(创建 roles/bindings)
自建 `Role`(对 `Role` 和 `Binding` 资源 CRUD)+ 对应 `Binding`。

### 4. Audit Admin
自建 `Role`(对 `Folder` 仅 `get`,`recursive: true`)+ `Binding`。

### 5. 组合(角色聚合 Role Aggregation)
建聚合 `Role`(`aggregationRule.selectors.matchLabels` + `rules: []` 留空),在子 role 打对应 label 即自动聚合。

> 完整 YAML 示例见原文档;核心资源结构见 [[授权模型 (Role-Binding-PathBinding)]]。

## 防提权(务必记住)

- 只有已拥有该 role 全部权限才能创建/更新该 role。
- 只有已拥有被引用 role 全部权限才能创建/更新 binding。
- `RuleRestriction` 可限定到特定属性。
